# AI 감지기 출시 준비

현재 구현은 한국어 iOS 앱 + Fastify 서버입니다. 참고 사이트 `aidetect.firesyss.com`은 타사 사이트이며 서비스 주소로 사용하지 않습니다. 아래 설정과 실제 결제 검증 전에는 판매를 시작하지 마세요. 법률 문서는 실제 운영 정보가 없는 **검토용 초안**입니다.

## 먼저 할 일

1. **본인 도메인과 연락처**: HTTPS 도메인을 준비하고 `/privacy`, `/terms`, `/support`를 공개하세요. `ios/project.yml`의 `API_BASE_URL`, `PUBLIC_WEBSITE_URL`을 변경한 후 `xcodegen generate`를 실행합니다. 기본 Release 주소는 의도적으로 `example.invalid`입니다.
2. **사업자·약관 정보**: `.env.example`의 `LEGAL_*`, `SUPPORT_EMAIL`을 실제 정보로 채우세요. 상호·대표자·주소·사업자번호·통신판매업 신고번호 또는 적용 제외 근거, 개인정보 담당자와 시행일이 필요합니다. 사업자등록/통신판매업 신고 및 표시 의무 적용 여부를 관할 기관 또는 전문가에게 확인하세요.
3. **API 계약**: Sightengine(또는 이미지 전용 Illuminarty)과 GPTZero의 유료 API 계정/키를 준비하고 소비자용 유료 앱에서의 이용 허용 범위, 데이터 보관·학습 이용 조건, 처리 국가와 재위탁 업체를 확인하세요. 이미지/영상과 텍스트의 API 단가는 서로 다릅니다. 한국어 탐지 성능도 실제 샘플로 검증하세요.
4. **국외이전·보유기간 확정**: 아래 표를 업체별로 완성하고 개인정보처리방침에 반영하세요. 국외이전의 법적 근거와 별도 동의 필요 여부를 확인하세요. 현재 분석 전 동의 UI만으로 모든 법정 동의 요건이 충족된다고 가정하지 마세요.
5. **Apple 결제**: App Store Connect에서 계약·세금·은행 정보를 등록하고 아래 소모성 상품을 만드세요. 실제 가격은 App Store에서 선택하고 앱은 `Product.displayPrice`로 표시합니다. 서버 인증서와 결제 알림 설정 후 Sandbox에서 구매·취소·대기·중복 재전송·재실행·환불을 확인하세요.
6. **앱 심사**: 개인정보처리방침 URL, 고객지원 URL, App Privacy 응답, 연령 등급, API로 자료를 전송한다는 설명을 실제 동작과 일치시키세요. Keychain Sharing과 App Group을 Apple 개발자 팀에 설정하고 실기기에서 메인 앱/공유 확장이 같은 지갑을 사용하는지 검증하세요.

코드는 원본 텍스트·이미지를 DB에 보관하지 않습니다. 영상은 길이 검증용 임시 파일을 생성하고 `finally`에서 삭제합니다. 서버 강제 종료로 남은 임시 파일은 호스트/컨테이너 재시작 시 정리하도록 운영해야 합니다. 결과는 재시도 대응을 위해 24시간 뒤 1분 주기로 제거합니다. 요청 ID·해시·상태와 거래·지갑 기록은 자동 만료하지 않으므로 확정한 보유기간에 맞춰 별도 정리·백업 파기 절차를 운영하세요. 외부 업체의 삭제/학습 미사용은 해당 계약 확인 후에만 약속하세요.

현재 서버에는 원문을 로그로 남기는 기능, 광고 SDK, IDFA 수집이 없습니다. 역방향 프록시·호스팅의 접속/IP 로그는 별도 설정 대상입니다. 기기 분석 이력 삭제와 서버 개인정보 삭제는 별개이며 서버 정보의 열람/삭제는 지원 문의로 처리합니다. 지갑 키 전체를 고객에게 요구하지 마세요.

## 횟수권과 가격

| 상품 ID | 횟수 | 목표 한국 가격 예시 | 회당 |
|---|---:|---:|---:|
| `com.kukjinman.aidetector.credits6` | 6 | 1,500원 | 250원 |
| `com.kukjinman.aidetector.credits20` | 20 | 5,000원 | 250원 |
| `com.kukjinman.aidetector.credits50` | 50 | 12,500원 | 250원 |

가격은 **제안값이며 등록되거나 확정된 가격이 아닙니다**. 최소 결제를 약 1달러 이상으로 운영하려면 미국 기준 가격을 1.00 USD 이상인 지원 가격으로 직접 선택하세요. Apple의 가격표·지역별 가격·환율에 따라 KRW 예시와 USD 조건을 동시에 맞추기 어려울 수 있으므로 실제 상품 화면에서 확인하세요. “인앱결제는 반드시 1달러 단위”라는 Apple 규칙은 아닙니다. [Apple 가격 설정 안내](https://developer.apple.com/help/app-store-connect/manage-in-app-purchases/set-a-price-for-an-in-app-purchase)

원가 100원, 판매가 250원을 가정하면 수수료만 15%일 때 `250×0.85−100=112.5원`, 30%일 때 `250×0.70−100=75원`입니다. 세금·환전·호스팅·실패한 API 호출·환불·운영비를 제외하기 전 금액이며 순이익이 아닙니다. Small Business Program에 승인되면 적용되는 15% 조건을 확인하세요. [Apple 프로그램 안내](https://developer.apple.com/app-store/small-business-program/)

영상은 여러 프레임으로 과금될 수 있어 이미지 1장과 원가가 같다고 가정하면 안 됩니다. 현재 10초 제한, 5초 간격, 샘플 점수 평균을 사용합니다. 실제 API 청구서를 확인하고 유형별 원가에 맞춰 상품 가격이나 차감 횟수를 조정하세요. 지금 구현은 세 유형 모두 성공당 1회입니다.

상품의 횟수는 서버 `src/billing/ledger.ts`가 결정합니다. 이미 판매한 상품의 지급 횟수를 바꾸면 지연 지급된 구매의 조건이 달라질 수 있으므로 새 상품 ID를 발급하세요. 구매한 미사용 크레딧은 만료시키지 않습니다. [Apple 심사 지침 3.1.1](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase)

## Apple 서버 설정

- [Apple PKI](https://www.apple.com/certificateauthority/)에서 필요한 Apple 루트 인증서(DER)를 내려받아 `backend/certs/`에 보관합니다. 임의 사이트의 인증서를 신뢰 루트로 사용하지 마세요.
- `APPLE_ROOT_CA_PATHS`, `APPLE_BUNDLE_ID`, Production의 숫자 `APPLE_APP_ID`, `APPLE_ENVIRONMENT`를 설정합니다. 인증서 검증은 Apple 공식 Node 라이브러리의 `SignedDataVerifier`와 온라인 인증서 상태 확인을 사용합니다.
- App Store Server Notifications V2를 `https://본인도메인/v1/apple/notifications`에 연결합니다. REFUND/REVOKE 알림을 검증하고 횟수를 회수합니다. 웹훅 실패/누락 감시 및 Apple 거래 대조는 출시 운영 절차로 마련하세요.
- **Sandbox와 Production은 서버·DB를 분리**합니다. TestFlight도 Sandbox 결제를 사용하므로 테스트 빌드에는 Sandbox 서버를 지정합니다. 운영 DB에 테스트 크레딧이 유입되지 않게 하세요.
- 앱은 검증된 StoreKit 거래 JWS를 서버에 제출하고, 서버가 지급을 확인한 뒤 `finish()`를 호출합니다. 거래 ID 중복 충전과 타 지갑 재사용을 막습니다. 시작 시 미완료 거래를 다시 확인합니다.
- 지갑 복구키는 공유 Keychain에 저장합니다. 설정에서 키를 별도 안전한 장소에 보관하면 다른 기기에서 연결할 수 있습니다. 소모성 구매를 Apple 일반 구매 복원만으로 다시 지급하지 않습니다.
- 복구키를 잃은 경우 Apple 거래 증빙과 지갑 정보를 대조하는 별도 지원 절차가 필요합니다. 현재 관리자 복구 자동화는 포함하지 않습니다.

## 서버와 데이터 운영

Node 24 이상과 `ffprobe`가 필요합니다. Docker 이미지에는 ffmpeg 패키지가 포함됩니다. 로컬 영상 개발에는 `brew install ffmpeg`를 사용하세요. 환경변수는 `node --env-file=.env --import tsx src/server.ts` 또는 배포 환경에서 주입합니다.

`NODE_ENV=production`에서는 실제 이미지 탐지 API, 결제 활성화, 법률 필수 필드가 없으면 시작하지 않습니다. 이 검사는 값 존재 여부만 검사하며 법률적 적정성을 보증하지 않습니다. API 키는 서버에만 저장하고 앱에 넣지 마세요.

SQLite 지갑은 `BILLING_DB_PATH`에 저장하며 Docker의 `billing-data` 볼륨으로 보존됩니다. **하나의 DB에는 서버 프로세스 하나만 실행**하세요. 재시작 시 미완료 예약을 환급하므로 다중 인스턴스/무중단 중첩 기동에는 적합하지 않습니다. 수평 확장 전에는 작업 임대와 트랜잭션을 지원하는 공유 DB로 이전해야 합니다. DB 백업·복원과 디스크 가득 참 감시도 필요합니다.

TLS 역방향 프록시에 요청 본문 최소 15MB, 업스트림 제한시간 130초 이상을 설정하세요. 프록시에서 별도 속도 제한을 적용하세요. 서버의 기본 제한은 연결 IP 기준 30회/분이므로 단일 프록시 뒤에서는 모든 이용자가 같은 제한을 공유합니다. 신뢰할 프록시 주소만 검증한 뒤 프록시 IP 처리 정책을 조정하세요.

외부 API 및 Apple 실제 결제는 키/상품 등록 전에는 종단간 검증할 수 없습니다. 모의 테스트 결과를 실제 탐지 성능이나 구매 성공 증거로 사용하면 안 됩니다. Instagram은 서버 IP에서 미리보기 접근을 차단할 수 있으며 이 경우 실패 처리·환급합니다. TikTok 및 임의 사이트 URL은 지원하지 않습니다.

## 마케팅 문구

> 외부 AI 탐지 API를, 필요한 만큼 합리적으로.
> 구독 부담 없이 텍스트·사진·짧은 영상의 AI 생성 가능성을 확인하세요.
> 필요한 횟수만 구매하고, 분석이 성공했을 때만 사용합니다.

가격 등록 후 실제로 회당 250원이 맞는 상품에는 “6회 1,500원, 회당 250원”처럼 검증 가능한 문구를 사용하세요. API 원가는 실제 계약 단가로 확인하기 전 광고에 단정하지 마세요. “100% 정확”, “업계 최저가”, 사용하지 않는 업체 로고·제휴 표현은 근거 없이 넣지 마세요.

## 검토 기준

- [개인정보 보호법](https://www.law.go.kr/법령/개인정보보호법): 처리방침 공개 및 국외이전 요건을 실제 사업 구조에 맞춰 검토.
- [전자상거래 등에서의 소비자보호에 관한 법률](https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률): 사업자 표시, 청약철회와 디지털 콘텐츠 공급 관련 의무 검토.
- [GPTZero API](https://gptzero.me/developers), [Sightengine 영상 분석](https://sightengine.com/docs/ai-generated-video-detection): 제공 범위·데이터 정책·원가를 계약 시 확인.

2026-09-16 기준 작업 메모이며 최종 법률 검토를 대신하지 않습니다.

추가 이미지 제공업체 `AI_PROVIDER=illuminarty`를 선택하면 이미지 전용으로 동작합니다. 제공업체 이름과 영상 지원 여부를 서버 설정 API가 앱에 전달하며, 영상 요청은 차감 전에 거절됩니다. 기본 이미지·영상 제공업체는 Sightengine입니다.

로컬 개발에서 Apple 상품 등록 전 실제 이미지 API를 확인하려면 `.env`의 `ALLOW_UNBILLED_LOCAL_API=true`와 `npm run dev`를 사용합니다. 이 모드는 `NODE_ENV=development`에서만 동작하고 127.0.0.1에 바인딩하며 전달된 프록시 요청을 거절합니다. 서버 지갑 횟수는 차감하지 않지만 **외부 API 비용은 발생**합니다. 배포 시 끄고 운영 결제를 설정하세요. `npm run dev`는 `.env`를 자동 로드합니다.
